# 事实核查

知识类、测评类、价格类视频，错一个数字比画面难看严重得多：观众会截图，平台会限流，作者要出来道歉。这一节规定事实从哪来、怎么记、什么时候拦住不让渲。

## 什么时候要做

稿子里出现下面任何一种，就要走这一节：

- 价格、额度、套餐档位、优惠和截止日期

- 数据、比例、排名、增长率

- 产品功能、上线时间、支持哪些平台

- 对第三方的描述（某公司做了什么、某人说过什么）

- 「最新」「现在」「今年」这类会过期的说法

纯观点、纯个人经历、纯虚构的示意例子可以不查，但也要在表里标出来（观点 / 示意）。

## 流程

### 1. 先列事实

文字稿写完（或用户给的稿子拿到）之后：

```bash
python3 scripts/factcheck.py extract audio/narration.txt source/factcheck.md
```

它把带数字、价格、日期、「免费 / 上线 / 官方」这类词的句子都列成表。宁可多列，观点句标「观点」就过去了。

### 2. 调研

- **先一手，后二手**：官方定价页、帮助文档、官方公告、发布会 > 主流媒体报道 > 用户帖子。价格和额度一定要自己打开官方页面核对，搜索摘要不算。

- **每条都记出处和日期**：URL 写进「出处」，页面的发布或更新日期写进「来源日期」；页面没写日期的，写访问日期并在备注里注明。

- **说法冲突时**：以官方为准，并在备注里写清冲突点；没有官方口径的，标「二手」或者从稿子里删掉，不要取中间值。

- **限时的东西单独记**：活动截止日、限量名额、限时加赠，在备注里写截止日期，交付时单独列给用户。

- **能并行就并行**：有子 agent 时，按调研对象拆开（一个产品一个 agent），用下面的提示词模板，让它们只返回带出处的结构化事实，不要写成稿子。

调研子 agent 提示词模板：

```text
今天是 <日期>。请调研 <对象> 截至现在的 <要查的方面>，用于一条面向 <受众> 的视频文字稿，事实必须准确。
逐条查清并给出来源 URL 和该来源的发布/更新日期：
1. <要点 1>
2. <要点 2>
……
方法：优先官方页面和官方公告，再用媒体报道和用户帖子交叉验证。查不到或互相矛盾的，明确标「未核实」并说明冲突点，不要猜数字。
输出：按上面各点分节的结构化报告，每个事实后附 [来源 URL，日期]；最后单列「最可能已变化 / 不确定的事实」。不要写成视频稿。
```

### 3. 按核查结果改稿

| 状态 | 稿子里怎么写 | 画面上怎么放 |
|---|---|---|
| 已核 | 正常陈述 | 可以放大字和数字 |
| 二手 | 写明来源性质：「有用户反馈」「报道称」「媒体实测」 | 不放成大标题 |
| 计算 | 正常陈述，备注写算式 | 可以把算式放上屏 |
| 示意 | 用「比如」「示意」引出 | 画面上标「示意」 |
| 观点 | 第一人称判断 | 正常 |
| 未核实 | 删掉，或改成不带数字的说法（「以 App 当期为准」） | 不放 |

另外两条：

- **画面上的每个数字都要在表里**。画面上算出来的派生数字（省了 43%、时薪约 60 元）同样要进表，状态「计算」，备注写算式。

- **日期不进封面**。「价格截至某日」放在结尾一句旁白和简介里，封面和开头不放日期。

### 4. 给用户确认

文字稿交给用户确认时，把核对表一起给：哪些是官方核过的、哪些是二手、哪些故意没写以及原因。用户确认的是稿子加这张表。

### 5. 出片前过闸

```bash
python3 scripts/factcheck.py gate source/factcheck.md --narration audio/narration.txt --page index.html
```

- 有任何一条没填状态、还是「未核实」、「已核 / 二手」没有 URL、「计算」没有算式，退出码为 1，**不渲正式版**。

- 警告不拦，但要逐条看：稿子改了表没跟上、某句话已经从稿子里删掉、画面上出现了稿子和表里都没有的数字（多半是示意，要么进表要么删）。

### 6. 发布前再看一次

交付说明里单列「发布前要再核的」：所有带截止日期的活动、所有标了「最新 / 现在」的价格。距离核查超过一周的，发之前重新打开官方页面看一眼。
